# 会话协议（针对"无连续记忆"的工程约束）

> 大模型没有稳定的时间感：不调用就不存在，上下文会被截断，记忆会漂移。
> 因此在项目里，**状态与事实必须外置到文件**，而不是留在对话中。
> 本协议是所有 AI 会话（含子代理）的强制流程。

## 一、会话开始（5 分钟恢复上下文）

按顺序读，**不要凭记忆开工**：

1. `docs/STATE.md` —— 当前版本、commit、已验证数字、未决风险、下一步
2. `docs/PROGRESS.md` —— 最近 3 条轮次记录（发生了什么、验证结果）
3. `docs/LESSONS.md` —— 全文扫一遍（尤其涉及数值/生命周期/UI层级/打包的条目）
4. `docs/ARCHITECTURE.md` 中与本次任务相关的章节
5. 最近 1-3 份 `docs/reports/*.md`（只读与任务相关的）

如果 STATE 与代码不一致：**以代码 + 命令输出为准**，并立即修正 STATE。

## 二、事实分级（防幻觉累积）

所有结论必须标注来源等级：

| 等级 | 定义 | 允许的表述 |
|---|---|---|
| **已验证** | 有命令输出、测试数字、截图或真机反馈 | "已验证：166 断言全过" |
| **静态推断** | 只读过代码，未运行 | "[推断] 可能导致…" |
| **未知** | 无证据 | "未验证" / "不清楚" |

规则：
- 报告里 🔴 严重级结论必须附**可复现命令 + 输出摘要**，否则降级为 `[推断]`。
- 子代理的结论默认是 `[推断]`，除非它贴出了运行输出。
- 禁止把"上次说过的"当作事实；必须回到 STATE 或 git 历史核对。

## 三、声明与验证分离

- 子代理只负责**实现与自检**，并在报告中声明"我验证了什么、用什么命令、输出是什么"。
- 主会话或终验子代理负责**独立复验**：重跑命令，不看子代理结论。
- 两者结论冲突时，以**实际命令输出**为准，并把冲突记入 LESSONS。

## 四、会话结束（必须做的三件事）

1. **更新 `docs/STATE.md`**：最后更新时间、版本号、git commit、单测/冒烟数字、新增风险、下一步。
2. **追加 `docs/PROGRESS.md`**：本轮做了什么、验证结果、未完成项、下一步。
3. **按需更新**：
   - 结构性决策 → `docs/DECISIONS.md`（新 ADR，不修改旧条目）
   - 踩坑 → `docs/LESSONS.md`（现象/根因/修复/提前发现）
   - 专项报告 → `docs/reports/YYYY-MM-DD-<topic>.md`
4. **提交前必须跑**：`bash scripts/verify.sh`（导入 + 单测 + 冒烟），并确认输出的验证记录已归档到 `docs/reports/verify-*.md`。

## 五、验证闭环（RSI 的"自我评估"部分）

```
改动 → verify.sh（自动）→ 结果写入 docs/reports/verify-<时间戳>.md
     → 若有回归：定位根因 → 修复 → 重跑 → 把根因写进 LESSONS
     → 若通过：更新 STATE/PROGRESS → 提交 → 可选打包
```

- **可重复**：同一命令在任何会话、任何环境下产出同格式结果。
- **可比较**：每次记录都带时间戳与 commit，能纵向对比"这轮比上轮好在哪"。
- **可审计**：报告与验证记录入库，不依赖对话历史。

## 六、禁止事项

- ❌ 不读 STATE 就开始改代码
- ❌ 把子代理的"已完成"当作已验证
- ❌ 用"应该没问题"替代运行验证
- ❌ 修改平衡数值却不更新 DECISIONS / 不跑单测
- ❌ 在对话里做"口头承诺"，不写进文档
- ❌ 删除或篡改历史报告（修正另开 `-fix` 文件）
