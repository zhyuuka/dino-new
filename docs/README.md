# 文档与报告规范

本目录存放**团队可长期维护**的工程文档。原则：结论落盘，不留在对话里。

## 目录结构

```
docs/
├── README.md            # 本文件：规范与索引
├── ARCHITECTURE.md      # 架构现状评估 + 技术债 + 重构路线图
├── QA.md                # 质量评估：测试覆盖、冒烟结果、已知缺陷
├── PROGRESS.md          # 进度日志：每轮做了什么、验证结果、下一步
└── reports/             # 子代理与专项报告（只增不改，作为历史记录）
    └── YYYY-MM-DD-<topic>.md
```

## 子代理报告规范（强制）

1. 子代理必须把**完整报告**写入 `docs/reports/YYYY-MM-DD-<topic>.md`，禁止只回聊天。
2. 回复给主会话的内容 ≤200 字，只包含：一句话结论 + 关键数字 + 文件路径 + 风险项。
3. 报告文件必须包含：背景、做法、改动清单（文件:行号）、验证结果、风险与回退方式、引用来源。
4. 报告一经写入不再修改；后续修正另开 `-fix` 文件并在 ARCHITECTURE/QA 里引用。

## 评估文档更新节奏

- 每完成一批改动：更新 `PROGRESS.md`（新增一轮记录）与 `QA.md`（测试/冒烟数字）。
- 架构发生结构性变化（拆类、换模式、改数据层）：更新 `ARCHITECTURE.md` 对应章节。
- 每轮结束前必须写：改了什么、验证了什么、还剩什么风险。
