# 决策记录（ADR）

> 每条决策写清：**当时的问题、选了什么、为什么不选别的、什么条件下应重新评估**。
> 目的：避免下一轮会话在不知道原因的情况下推翻正确设计，或重复讨论已否决方案。
> 编号永不复用；被推翻时写 `状态：已被 ADR-xxx 取代`，不删除原文。

---

## ADR-001 · 不上 ECS
- **日期**：2026-10-18
- **问题**：是否用 ECS 统一管理恐龙实体与系统。
- **决策**：不上。使用"浅继承（DinoActor）+ 组件"。
- **理由**：单机 3D、实体 10-20 只（兽群峰值 ≤19），Godot Node 本身即组合单元；ECS 会引入 World/System 间接层，并失去编辑器摆场景能力。Reia 上 gecs 是因为服务器权威与联机确定性，与本项目前提不同。
- **重新评估条件**：实体 > 1000 且同一套 per-frame 逻辑，或加入联机确定性模拟。

## ADR-002 · 单场景 + 运行期节点重置，不做整场景重载
- **日期**：2026-10-18
- **问题**：死亡/重开后如何回到游戏。
- **决策**：保留世界（地形/植被/资源点/蛋），只释放并重建运行期节点（玩家/AI/HUD/触屏/事件）。
- **理由**：移动端重建 3.2 万三角碰撞体与数百模型会导致数秒卡顿；实测改为重置后卡顿消失。代价是需要手工维护释放清单（已登记 R2，将由 GameFlow 收敛）。
- **重新评估条件**：世界资产变轻（<1s 可重建）或需要跨局完全隔离状态时。

## ADR-003 · 地形碰撞用 HeightMapShape3D 升采样，而非 trimesh
- **日期**：2026-10-18
- **问题**：`create_trimesh_collision()` 构建 3.2 万三角凹形碰撞，移动端慢、内存高。
- **决策**：把 129×129 @2m 高度场升采样到 257×257 @1m，交给 HeightMapShape3D（Godot 4.4 格距固定 1m，无 cell_size）。
- **理由**：碰撞内存 3MB→258KB、构建 ~105ms→~10ms；升采样保证与视觉网格同范围同中心，物理与 `get_height()` 一致。
- **重新评估条件**：Godot 支持自定义格距，或地形改为分块流式。

## ADR-004 · 自然物与植物用 MultiMesh 合批，且按块/槽位管理
- **日期**：2026-10-18
- **问题**：每棵树木/每株植物一个节点 + 一次绘制，Mobile 渲染器无自动 instancing。
- **决策**：树木岩石按 64m 分块、按 slug 建 MultiMesh；植物用 per-slug MultiMesh 池 + 槽位 swap-remove。
- **理由**：森林图 draw call 约 338→45；自然物 71 实例合并到 43 批次；加载从 1.27s 降到 0.2-0.4s。
- **代价**：MultiMesh 无逐实例可见性（靠分块 + custom_aabb），植物需自管槽位；块角可见距离最远约 90m（雾中不可见）。
- **重新评估条件**：primitives > 150k 需要更细分块；或需要逐实例 LOD。

## ADR-005 · autoload 上限 4 个，且不存放 Node 引用
- **日期**：2026-10-18
- **决策**：现有 GameState / AudioManager / Achievements / FrameProfiler 四个；SaveManager 保持静态类。
- **理由**：autoload 只适合"跨场景存活、自管数据、不碰场景节点"的系统；存放 Node 会导致生命周期泄漏与隐式依赖。
- **重新评估条件**：新增第五个 autoload 时，必须先证明它无法由 Main 显式装配。

## ADR-006 · 存档：单一 Repository + 显式迁移链，不用 Resource 存运行时档
- **日期**：2026-10-18
- **决策**：JSON + PlayerProfile + SaveRepository（原子写、写前备份、v1→v2 迁移、损坏/未来版本隔离）；Resource 只用于静态配置，不存存档。
- **理由**：Resource 是共享引用，存运行时状态会串档；JSON 可 diff、可迁移、可外部修复。
- **重新评估条件**：需要多槽位/云存档时，在 Repository 接口层扩展，不改存储格式的原子性要求。

## ADR-007 · EventBus 只保留给"跨场景、多监听、fire-and-forget"事件
- **日期**：2026-10-18
- **决策**：Main 与子系统之间保持直接信号连接；成就/横幅这类广播才允许总线。高频事件（每帧/每次命中）绝不走总线。
- **理由**：总线会让调用链不可追踪；本项目 Main 已是显式装配点，无需总线解耦。
- **重新评估条件**：出现 3 个以上互不相关的监听者且不属于同一子系统。

## ADR-008 · 服务端/网络暂不做，但存档与实体接口留扩展点
- **日期**：2026-10-18
- **决策**：第 4 阶段多人联机不在当前范围；SaveRepository 与 GameFlow 预留接口，不提前实现网络层。
- **理由**：单人 APK 优先保证可玩与稳定；提前抽象网络会显著增加复杂度且无验证场景。
- **重新评估条件**：单人版本稳定且明确要做联机时。
